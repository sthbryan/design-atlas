# VibeUI

## What it is

VibeUI is a free library of short layout prompts for AI UI generators. Each prompt describes only the structure of a section (a split-screen login, a three-tier pricing table, a bento feature grid) and ends by telling the model to match the style of a screenshot you attach, so the structure and the look come from separate inputs.

## When to open it

- When an AI tool keeps producing generic sections and you want to name the exact layout you mean.
- When you're assembling a landing page or app shell section by section and want a checklist of common layout variants.
- When you want to pair a structural prompt with a reference screenshot from an inspiration gallery.

## Most useful

- 92 prompts in 15 categories: auth forms, pricing, features/bento, hero sections, CTA banners, stats bars, nav bars, testimonials, footers, FAQ, dashboards, onboarding, blog/content, contact and a bonus set (comparison table, announcement bar, cookie banner, 404 page, loading skeleton).
- Each card pairs a short layout name and description with a one-click "Copy prompt" button.
- Hero variants cover the usual options: centered text plus screenshot, split, video background, animated gradient mesh, terminal/code, floating UI cards, oversized type and inline email form.
- Keyboard search (slash to focus, Esc to clear) and category anchors in the sidebar.

## Using it with agents

The whole site is meant to be pasted into an agent: copy a prompt, paste it into any AI coding or UI tool (Cursor, Claude Code, v0, Lovable, Bolt), and attach a screenshot of the style you want. The "Generate in GlowUp" buttons send the same prompt to GlowUp UI. There is no MCP, llms.txt or API.

## Watch out for

- Prompts are one or two sentences each; they set the skeleton but leave spacing, states, accessibility and responsiveness to the model.
- The results depend heavily on the screenshot you attach, and that screenshot's owner's rights still apply.
- GlowUp UI promotion is on every card; the prompts work without it.

## Reusable ideas

- Separating "structure prompt" from "style reference" gives the model a skeleton to fill instead of asking it to guess both at once.
- A fixed closing sentence reused across every prompt makes a library consistent and easy to extend.
- Listing several named variants per section type (eight heroes, eight pricing layouts) doubles as a design checklist before you start.
