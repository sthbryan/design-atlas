# Charm

## What it is

Charm is a family of Go tools for terminal interfaces, styling, forms, Markdown and shell workflows. Its homepage uses a vivid purple and pink atmospheric backdrop, large rounded typography and an oversized terminal product image to give several small developer tools one memorable identity. The products themselves are open source; the page is a visual example of a developer-tools brand site.

## When to open it

Use it when a technical product family needs a distinctive marketing page, or when exploring how terminal applications can express hierarchy, state and personality with text alone.

## Most useful

- **Product family section**: Bubble Tea, Lip Gloss, Huh, Wish, Glamour and Bubbles each get a compact purpose statement and direct repository link.
- **Crush feature**: a large screenshot and short copy make the terminal AI client the visual anchor without hiding the broader library ecosystem.
- **Tone and visual system**: saturated gradients and playful names contrast with legible navigation and concise product descriptions.
- **Libraries**: Bubble Tea handles app state and rendering; Lip Gloss provides layout and styles; Bubbles supplies reusable controls.

## Using it with agents

There is no MCP or agent API for the homepage. The linked public repositories include README files and upgrade guides written for developers and coding agents. For library use, start with the specific project's repository and check its current version and licence.

## Watch out for

- The visual brand and product names are not reusable assets; use the page as a reference only.
- Charm's collection includes several separate products, and the licence and availability of each should be checked individually. Bubble Tea, Lip Gloss and Bubbles state MIT.
- Terminal layouts depend on the target terminal's width, colour support and input behavior; browser mockups do not show those constraints.

## Reusable ideas

- Give each product a short, specific verb-based description so a broad product suite remains scannable.
- Use one strong product screenshot to establish the brand, then reserve smaller cards for adjacent tools.
- Connect a library description directly to the repository where a developer can inspect its real interface and examples.
- Build personality through illustration, naming and colour while keeping core product information plain.
