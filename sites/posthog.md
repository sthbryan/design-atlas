# PostHog

## What it is

PostHog is a product analytics suite: one product covering trends, funnels, retention and dashboards, instead of a browser full of separate analytics tabs. The dashboards page is the reference for combining different insight types into shared views, which is the core of the product story.

## When to open it

- When a dashboard needs to mix charts, funnels and cohorts on one canvas instead of living in separate tools.
- When analytics pricing should start free and grow with usage, with the free tier stated plainly on the pricing page.
- When the product is also the demo: the marketing site, docs and product share the same visual language.

## Most useful

- Dashboards as composition: trends, funnels, retention and paths in one view, presented as the feature rather than dashboards as a folder of saved charts.
- The product pages lead with the workflow (instrument, analyze, see) instead of an exhaustive feature list.
- The site's design carries the product's argument: a dense, confident UI that looks like the dashboards it sells.
- Docs are extensive and product-shaped, matching an audience that reads docs as part of daily work.

## Using it with agents

- PostHog publishes an MCP server and an API behind project credentials.
- The public docs and product pages are the agent surfaces at review; live dashboards need an account.

## Watch out for

- Pricing at review is usage-based with a free tier, stated on the pricing page; confirm limits live before budgeting.
- Open source parts and hosted usage follow different licences; check the repository and terms for anything you self-host.
- Do not copy PostHog's dashboard UI or copy; study the composition approach instead.

## Reusable ideas

- Present dashboards as composition of insight types, not as storage for saved charts.
- Lead analytics product pages with the workflow (event, insight, view) before the feature list.
- Keep the marketing site's design language continuous with the product UI, so the demo story is credible.
