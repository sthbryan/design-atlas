# The Iconography Encyclopedia

## What it is

The Iconography Encyclopedia is a field guide to the vocabulary of icon design, published by an icon studio. It is a single alphabetical page of definitions that runs from abstract, accessibility and anatomy through boolean operations, corner smoothing and key lines to stroke weight, silhouette, wayfinding and white space. Each entry is a paragraph rather than a sentence, and the two halves of the craft sit together: the technical terms a vector tool uses, and the judgement terms a designer argues with.

## When to open it

- You are writing a spec, a naming convention or a review comment and need the word for a thing in a glyph.
- You have to brief someone on an icon set and want to define scope, style and consistency without inventing terms.
- A design critique is going in circles because "weight" and "visual weight" are being used interchangeably.

## Most useful

- **Construction terms**: anatomy, base and modifier, compound icon, key line, overshoot, optical corrections, pixel snapping, corner smoothing, stroke alignment and stroke width profile. These are the words that make a Figma or Illustrator conversation precise.
- **Quality terms with distinctions kept**: clarity, legibility, readability and recognizability are defined separately, as are icon family, icon set, icon library and icon system — four terms that teams routinely collapse into one.
- **Set-level terms**: cohesiveness, completeness, consistency, and the trio of navigability, metadata and naming convention, which are the ones that decide whether a library is usable by anyone but its author.
- **Judgement terms**: brevity, silhouette, visual weight, personality, and the note that squinting at a glyph is a legitimate test of its shape.
- **Platform and file vocabulary**: app icon, favicon, product icon, SVG, PNG, GIF, export, versioning, deprecation, plus Figma-specific terms such as instance and vector network.

## Using it with agents

No agent channel at review: no `llms.txt`, no API. It is useful to an agent only indirectly, as a place to pull precise terms into a prompt or a specification, so quote a short definition rather than pasting the page.

## Watch out for

- It is a glossary, not a tutorial. Definitions assume you know how to draw, and there is little guidance on applying them.
- The page is one long scroll with no per-term URLs, so you cannot link a colleague to a single definition. Cite the term and the page.
- Some entries describe one studio's practice, such as the prefix pattern in a naming convention example, rather than a rule. Adapt rather than copy.
- No date or version is shown on the entries, so a tool-specific term may already be out of date.
- The studio's own icons are not offered here. This is reference text, and the entries carry no reuse licence.

## Reusable ideas

- Publish a glossary as a single alphabetical page; it is cheap to maintain and it is the page a team links to most.
- Define the near-synonyms separately and say where they differ, instead of one loose entry for all of them.
- Put technical and judgement terms in the same list, so craft vocabulary is not split from the software's vocabulary.
- Name the four levels of an icon offering, from family to system, before arguing about which one you need.
