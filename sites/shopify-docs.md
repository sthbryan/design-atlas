# Shopify Developer Docs

## What it is

Shopify Developers is the documentation home for a large merchant platform, and its most useful design decision is the top-level wayfinding: apps, storefronts, agents and references are separated as distinct areas, because a storefront developer and an app developer are doing genuinely different work.

## When to open it

- When docs cover very different audiences (app builders, theme developers, storefront teams), and one flat sidebar would blur them together.
- When a platform keeps adding surfaces (agents, AI integrations) and needs room to grow without rethinking navigation.
- When the distinction between "build a thing" and "look something up" needs to be visible in the structure.

## Most useful

- Top-level sections map to real developer tasks instead of internal product names, so each audience sees its own home first.
- Reference content is kept apart from building guides, so lookup tasks stay short.
- The structure has room for new surfaces: an agents area can appear as a first-class entry instead of a page buried under apps.
- Search and contextual navigation keep a large docs tree usable without deep hierarchies.

## Using it with agents

- Shopify publishes an llms.txt for the developer docs at review, and GraphQL/REST APIs behind partner accounts.
- The top-level structure is the agent entry point: pick the audience section first, then follow its guides and references.

## Watch out for

- Platform building requires a partner account and follows app terms; the docs are a look-only reference without one.
- App review, payments and theme rules are stated in the platform docs themselves; read the relevant section before designing a flow.
- Do not copy Shopify's docs layout or copy; study the wayfinding approach instead.

## Reusable ideas

- Map top-level docs sections to audiences or tasks, not to internal teams or product codenames.
- Reserve a first-class slot for new surfaces so they do not need a navigation redesign when they arrive.
- Keep "build" guides and "look up" references as separate top-level paths in large docs sites.
