# Web Design Museum

## What it is

A museum of the web before it flattened out: screenshots and videos of websites, mobile apps, desktop software and Flash games from the 1990s to the late 2000s, each labelled with its name and year. The catalogue is organised twice over. By object type — websites, Flash games, apps, software — and by exhibition, which is where the curatorial thinking shows: "Web Design in the 90s, 1991–1999", "Y2K Aesthetic, 1996–2005", "Search Engines in the 90s, 1995–1999", "Bad and Ugly Websites, 1996–2006", "Pixel Art in Web Design, 1996–2005".

The museum's own design is deliberately recessive: a light page, cards that are little more than an image with a name and a year beneath it, and section headings that do nothing but name the shelf. The restraint is the point — a decorated frame around 1996 screenshots would fight them.

## When to open it

Open it when a brief calls for a period look and you need the actual vocabulary rather than a modern pastiche: the bevel-heavy buttons, the table-based three-column layout, the spinning envelope, the pixel type that was legible at 640 pixels wide. Also useful for explaining to a client what a redesign changed, since the same brand often appears at several dates.

## Most useful

- **Exhibitions grouped by period and style**, which is the fastest way into a specific era without knowing which year a look peaked.
- **Year on every card**, so a single brand's sequence (Mattel 2005, 2008, 2015, 2018, 2020) reads as a history of its own design system.
- **Platform indexes for apps** — iPhone, Android, Windows Phone, BlackBerry, Apple Watch — that document interfaces most galleries never collected.
- **Software by category**, including browsers and graphics tools, useful for chrome, menus and dialog patterns that no longer exist.
- **Quizzes**, an unusual device that turns the archive into something you can play.

## Using it with agents

No `llms.txt`, API or MCP server at review, and the site answers automated requests with a Cloudflare challenge — plain `curl` got a 403 while the browser loaded the page normally. An agent therefore needs a real browser session to read it, and should not assume a failed fetch means the museum is down.

## Watch out for

- The archive stops at the late 2000s, so it documents a period, not current practice.
- Every screenshot belongs to its owner; the museum states that clearly, and none of it is yours to reuse in a mockup.
- Period pieces are easy to copy literally; the useful part is the constraint behind them, such as a fixed 640-pixel canvas, not the bevels.
- Automated access is blocked, which also blocks bulk research.

## Reusable ideas

- Name a collection by period and range ("Y2K Aesthetic, 1996–2005") so the scope is legible before you click.
- Stack an image, a name and a year, and nothing else, on a catalogue card.
- Keep the archive's own interface plain so the exhibits carry the colour.
- Group the same material two ways — by type and by theme — when the collection is large enough to browse from either direction.
