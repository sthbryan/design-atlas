# Cursor

## What it is

Cursor is an AI-first code editor, and its landing page is a study in product-led marketing for AI tools: instead of stock imagery of robots, the hero is the product itself, an interactive demo of the editing workflow the visitor is supposed to imagine using.

## When to open it

- When an AI tool's landing page must explain a workflow, not a feature list: showing the interaction beats describing it.
- When the product demo is the best piece of content, and the page should be built around it rather than beside it.
- When a developer audience judges by the editor UI, so the site design must look like the product, not like a campaign.

## Most useful

- The interactive demo as hero: the visitor sees the coding workflow immediately, in the product's own visual language.
- The page structure follows the workflow (prompt, edit, review) instead of a grid of features.
- The editor UI carried into marketing material, so the site and the product feel like one product.
- Copy stays terse and technical, which suits an audience that reads docs for a living.

## Using it with agents

- No agent channel is declared on the marketing site at review; the product itself is the agent surface, behind an account.
- The public pages and docs are the agent reference; the editor needs installation and credentials.

## Watch out for

- Plans and model pricing at review are stated on the pricing page; confirm live before budgeting, and note that usage-based plans vary.
- The demo on the page may not include every current feature; check the docs for the latest state.
- All content is proprietary and look-only; study the demo-first structure, do not reuse the UI or copy.

## Reusable ideas

- Make the interactive demo the hero when the workflow is the selling point, instead of a static mockup.
- Structure an AI tool's landing page around the workflow (input, action, result), not a feature grid.
- Keep the marketing site visually continuous with the product UI, so the page functions as a credible demo.
