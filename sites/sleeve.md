# Sleeve

## What it is

Sleeve puts the currently playing track on the desktop and lets you rebuild how it looks. Its page is organised as a settings tour, which is the right structure for a product whose value is customisation: themes, then artwork (scale, corner radius, shadow, lighting, shelf), then typography (which lines, which fonts, weights, sizes, transparency, colour, shadow), then layout and alignment, then a backdrop layer, then window behaviour and keyboard shortcuts with a custom HUD.

## When to open it

Open it when you are designing a customisable widget and need a reference for exposing many options without a wall of sliders, or when you are writing a type-controls panel: Sleeve lets each line of text take its own font, weight, size and transparency.

## Most useful

- **Grouped preferences**: artwork, typography, layout, settings, integrations. Each group has four or five named controls, not thirty.
- **Per-line typography**, which is rare and genuinely useful for a small widget.
- **Theme files** as a portable format, installable by double-click or drag and drop, so customisation becomes shareable.
- **A shortcut HUD** that shows what the keypress did, in the app's own visual language.
- **Integration list stated plainly** (Apple Music, Spotify, Doppler, Last.fm), with the account requirement named.

## Using it with agents

No `llms.txt`, MCP server or API was found at review. Themes are plain files, so an agent could in principle generate or edit a theme file, but the format is documented only inside the app's preferences at review.

## Watch out for

- Requires macOS 26 Tahoe, which excludes most machines at review.
- The page is long and every section repeats the same promise of customisation.
- Artwork treatment options multiply quickly; the page does not show what the combinations look like together.
- Last.fm scrobbling and Spotify likes need separate accounts.
- The desktop widget competes with wallpaper choice, and the page does not address legibility over busy wallpapers.

## Reusable ideas

- Tour the settings as the marketing: group by what the user changes, not by feature.
- Let a small widget's text lines be styled individually.
- Make the customisation portable as a file so people can share it.
- Show a HUD for keyboard actions so the effect is visible.
