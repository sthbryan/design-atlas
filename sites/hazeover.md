# HazeOver

## What it is

HazeOver dims everything except the window you are working in, and its page is a good example of explaining an invisible effect. There is no screenshot of a feature list; there is a claim, then a sequence of situations where the effect matters — a large display, several monitors, dark mode at night, too many windows open — each one a paragraph rather than a card. The two controls it exposes are named on the page: how dark the background goes, and how fast the transition is.

## When to open it

Open it when you need to describe a continuous, ambient behaviour in a landing page, or when you want a reference for a single-purpose utility page that trusts a plain column of text.

## Most useful

- **Effect before feature**: the first screen states what happens, not what the app contains.
- **Scenario list** instead of benefits: large display, multiple monitors, night work, typing into the wrong window.
- **Named controls** (intensity, animation speed) so the reader knows the effect is adjustable.
- **Separate settings for light and dark appearance**, which is the detail designers look for in a dimming tool.
- **Modifier behaviour**: pressing Fn suspends the dimming while dragging between apps.

## Using it with agents

No `llms.txt`, MCP server or API was found at review. The app can be automated through Shortcuts, Focus filters and AppleScript, so an agent or a shortcut can change the effect, but that is a system integration rather than a design surface.

## Watch out for

- The page is long and text-heavy, with the same claim restated several times.
- Pricing sits behind a trial and a Setapp listing; the page read does not show a number.
- The effect depends on contrast, so it interacts badly with already-dark interfaces unless tuned.
- Version requirements are stated in a small note under the hero.
- Its own site is not a design reference; the value is the copy strategy.

## Reusable ideas

- Describe an ambient effect with four concrete situations rather than a feature list.
- Name the two parameters the user will actually adjust.
- Support the app's light and dark appearances separately.
- Provide a modifier key to suspend the effect temporarily.
